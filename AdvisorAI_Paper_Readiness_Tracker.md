# AdvisorAI V3 — Autonomous Paper Trading Readiness Tracker

Baseline: 2026-11-14. Scope: `PAPER-V1`. This tracker defines the next ten jobs, not a percentage of the entire codebase.

**Verified: 1/10. Partial: 3. Open: 6. Release: NOT READY.** Partial evidence is real progress, but it does not increment the release count.

## Finish line

An owner starts one supervised release on an explicitly approved fake-funds venue profile. During the session, AdvisorAI independently collects approved data, generates or abstains on decisions, routes only approved paper orders through the deterministic RiskKernel and OMS, reconciles with the venue, records outcomes, and stops safely or alerts on faults. Its bounded research jobs can find papers and code, implement candidates, replay them independently, and save both positive and negative results. New strategies, models, venues and permissions are never self-approved.

First release: one reviewed sandbox execution venue and one approved strategy with multi-asset research (at least equity and bond exposures). Binance Testnet does not execute SPY or TLT. A strategy admitted for SPY/TLT research cannot simply be routed to Binance. Select a venue-compatible strategy for this release, or explicitly change the execution venue and requalify. “Autonomous” means no manual approval per cycle in an owner-started session. It does not mean 24/7 service, real capital, or unattended promotion.

## How we track it

1. Use only **OPEN**, **PARTIAL**, **BLOCKED**, and **DONE**. DONE means the row's entire acceptance criterion is met with a pinned commit/config, test or run artifact, and reviewer where specified. If evidence is invalidated, reopen the row and decrement the count.
2. Update this tracker after each completed run or substantive code review, including failed attempts. Use `ID | old → new | commit/config | evidence | blocker or next action`. Keep run paths private if they contain restricted data. Don’t report “90%.”
3. Keep the denominator at ten for PAPER-V1. Subtasks stay under their parent job. New tools or new markets go into a separate backlog unless the owner explicitly revises the release scope. Don’t silently downgrade acceptance criteria.
4. Keep one owner for each shared interface and one operator for sandbox writes. No concurrent changes to the same checkout or active session state.
5. At each handoff, give the current count, the rows that changed, the next runnable action, and any exact owner action. Do not restart unrelated work.
